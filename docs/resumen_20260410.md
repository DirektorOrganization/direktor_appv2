# Resumen de Cambios — 2026-04-10

## Tema: Insights configurables por módulo (parametrización)

---

## Contexto

La pantalla de Insights mostraba reglas de alerta con umbrales fijos codificados en `insight_rules.dart`. El objetivo era hacer esas reglas **configurables por proyecto y módulo**, guardando la configuración en SQLite, y exponer una UI para que el usuario pueda activar/desactivar reglas y ajustar los umbrales sin tocar código.

---

## Archivos modificados

### `lib/data/models/app_models.dart`
- Se añadió la clase `InsightRuleConfigRecord` con campos:
  - `projectId`, `module`, `ruleKey`, `isEnabled`, `thresholds` (Map<String,int>)
  - Método helper `threshold(name, defaultValue)` que retorna el valor configurado o el default.

---

### `lib/data/local/app_database.dart`
- Se añadió la tabla `insight_rule_config`:
  ```sql
  (codProyecto, desModulo, desRuleKey) PRIMARY KEY
  isEnabled INTEGER DEFAULT 1
  thresholdsJson TEXT DEFAULT '{}'
  updated_at TEXT
  ```
- Se registró `_ensureInsightRuleConfigStructures` tanto en `onCreate` como en `onOpen` para compatibilidad con instalaciones existentes.

---

### `lib/app/insights/insight_rules.dart`
- Se añadieron dos nuevas clases:
  - `InsightThresholdDef` — describe un umbral: `key`, `label`, `defaultValue`, `min`, `max`.
  - `InsightRuleDef` — describe una regla: `key`, `module`, `label`, `description`, `thresholds`.
- Se definieron dos catálogos completos:
  - `restrictionRulesCatalog` — 6 reglas para el módulo de Restricciones.
  - `actaReunionesRulesCatalog` — 6 reglas para el módulo de Acta de Reuniones.
- Se añadió la función `insightRulesCatalogForModule(module)` para obtener el catálogo por módulo.

---

### `lib/data/app_repository_insights.dart`
- Se añadieron dos funciones de acceso a la nueva tabla:
  - `_loadInsightRuleConfigsImpl` — lee configs de `insight_rule_config` para un proyecto+módulo.
  - `_saveInsightRuleConfigImpl` — upsert (replace) de una config.
- Se actualizó `_recalculateModuleInsightsImpl`:
  - Antes de calcular, carga las configs de cada módulo desde SQLite.
  - Pasa el mapa de configs a las funciones de construcción.
- Se actualizó `_buildRestrictionInsightsImpl`:
  - Acepta `Map<String, InsightRuleConfigRecord> configs`.
  - Resuelve todos los umbrales con `thresh(ruleKey, threshKey, fallback)`.
  - Aplica `enabled(ruleKey)` para saltarse reglas desactivadas.
- Se actualizó `_buildActaReunionesInsightsImpl` con la misma lógica.

---

### `lib/data/app_repository.dart`
- Se expusieron dos métodos públicos:
  - `loadInsightRuleConfigs({projectId, module})` → `List<InsightRuleConfigRecord>`
  - `saveInsightRuleConfig({projectId, module, ruleKey, isEnabled, thresholds})`

---

### `lib/app/state/app_controller.dart`
- Se añadieron dos métodos al controlador:
  - `loadInsightRuleConfigs(module)` — delega al repositorio.
  - `saveInsightRuleConfig({module, ruleKey, isEnabled, thresholds})` — guarda y ejecuta `bootstrap()` para recalcular insights en caliente.

---

### `lib/features/insights/presentation/screens/insights_module_screen.dart`
- Se añadió un botón de engranaje (`Icons.tune_rounded`) en la cabecera de la pantalla de Insights.
- El botón abre `_InsightConfigSheet`, un `ModalBottomSheet` que ocupa el 85% de la pantalla con:
  - Lista de todas las reglas del módulo actual (usando el catálogo).
  - Por cada regla: toggle switch para activar/desactivar.
  - Si la regla está activa y tiene umbrales: flecha para expandir editors de umbrales.
  - `_ThresholdEditor`: botones de +/- , campo de texto numérico con clamp, botón de reset al default.
  - Botón "Guardar y Recalcular" que persiste todas las configs en SQLite y recalcula los insights del proyecto activo.
- Se añadió `_InsightConfigSheetState` con carga asíncrona inicial de configs y estado local de edición antes de guardar.

---

## Flujo de datos

```
Usuario abre config
    → _InsightConfigSheet carga configs desde SQLite
    → Usuario ajusta reglas y umbrales
    → "Guardar y Recalcular"
        → saveInsightRuleConfig() × n reglas → SQLite
        → bootstrap() → _recalculateModuleInsights()
            → lee configs desde SQLite
            → aplica enabled/thresholds en _buildRestrictionInsightsImpl / _buildActaReunionesInsightsImpl
            → escribe nuevos module_insights en SQLite
        → _apply(data) → UI se actualiza vía AnimatedBuilder
```

---

## Notas técnicas

- Los umbrales se almacenan como JSON en `thresholdsJson` (`{"minDays": 2, "maxDays": 5}`), lo que permite añadir nuevos umbrales a futuro sin migración de esquema.
- Si no existe config para una regla en SQLite, se usan los valores default de `insight_rules.dart` (compatibilidad hacia atrás).
- La config es **por proyecto** (`codProyecto`): cada proyecto puede tener sus propios umbrales.
- El recálculo ocurre síncronamente dentro del `_runGuarded` del controlador y dispara `notifyListeners()` automáticamente.
