## 1. `rv2_tablero_screen.dart` — Vista principal definitiva

Este archivo es la pantalla central del módulo. Contiene tres vistas en una misma screen, seleccionables mediante un modal: **Tablero**, **Lookahead** y **Gantt**.

### Correcciones de linter
- Bucles `for` con llaves obligatorias.
- Renombramiento de variable interna `__name` → sin doble guion bajo.

### Modal de cambio de vista (`_ViewSwitcherSheet`)
- **Problema:** overflow al mostrar el modal en pantallas pequeñas.
- **Solución:** `showModalBottomSheet` con `isScrollControlled: true` + `ConstrainedBox(maxHeight: 0.90 * screenHeight)` + `SingleChildScrollView`.

### Vista Gantt (`_GanttView`) — `StatefulWidget`
- Header de dos filas: fila superior con spans de semanas ISO, fila inferior con abreviatura de día.
- Lista izquierda con separadores de frente (`_GanttItem.frontHeader`) y filas de restricción (`_GanttItem.row`).
- **Scroll horizontal sincronizado** entre header y body mediante dos `ScrollController` + listener con flag `_hSync` para evitar loops infinitos.
- **Multi-selección de restricciones** (`_sel1`, `_sel2` tipo `int?`) para definir relaciones FC/CC/FF/CF.
  - Banner de selección activa (`_GanttSelBanner`).
  - Modal `_RelationPicker` con 4 tipos de relación.
  - Confirmación via `SnackBar`.
- Fix: `Container` con `color:` y `decoration:` simultáneos → movido `color` dentro de `BoxDecoration`.
- Fix: tipo `_sel1/_sel2` era `String?`, corregido a `int?` para coincidir con `r.id`.

### Sección distribución (Tablero) — chips horizontales
- **Área:** `SingleChildScrollView(scrollDirection: Axis.horizontal)` + `Row` con un `_Chip` por área.
- **Frente/Fase:** `Column` con dos `SingleChildScrollView` independientes (uno para frentes, otro para fases).
- Cada chip seleccionable filtra la lista de restricciones en los tabs.

### `_TableroCard` — tarjeta de restricción (rediseño completo)
Estructura final de la tarjeta:
```
[ franja izquierda | contenido ]
```
- **Franja izquierda:** 4px normal; cuando `r.isOverdue` → 26px con el conteo rotado 90° (`RotatedBox(quarterTurns: 3)`) en texto blanco: `"$daysOverdue días"` + `overflow: TextOverflow.ellipsis`.
- **Fila 1:** título de actividad (`Expanded`) + `_SyncBadge` (22×22, verde=synced / naranja=pending).
- **Fila 2 (chips):** área OR frente+fase según `_DistMode` activo.
- **Fila 3:** descripción (1 línea, opcional).
- **Fila 4 (acciones):** ícono persona + responsable (`Expanded`) | estado▾ (abre `_StatusSheet`) | ✏️ editar | ↗ detalle — todo alineado a la derecha con `Expanded` en el nombre del responsable.

### `_StatusSheet`
- Modal con lista de estados del catálogo (`ctrl.catalogs.statuses`).
- Fallback a 3 opciones hardcoded si el catálogo está vacío: `pending`, `in_progress`, `completed`.

## 2. `restriction_form_screen.dart` — Formulario crear/editar (reescritura)

Pantalla unificada para crear y editar restricciones. El argumento `RestrictionFormArgs(restrictionId: int?)` determina el modo.

### Estructura visual
- **AppBar:** fondo `_D.primary` (azul), texto blanco.
- **Header:** contenedor con gradiente `0xFF0A66B7 → 0xFF1580D8`, ícono circular translúcido, título de pantalla + nombre del proyecto.
- **3 secciones** `_FormSection` (misma estructura para ambas pantallas):
  1. **Ubicación** → Frente (dropdown + crear nuevo), Fase (filtrada por frente + crear nueva), Área (dropdown).
  2. **Detalle** → Actividad (TextFormField), Descripción (multiline), Tipo (dropdown).
  3. **Planificación** → Fecha requerida (date picker personalizado), Responsable, Estado, Solicitante (read-only = usuario actual).
- **Botón guardar:** `FilledButton.icon` con spinner `CircularProgressIndicator` cuando `ctrl.isBusy`.

### Widgets de soporte
- `_FormSection`: contenedor con borde, cabecera con ícono y título en azul primario.
- `_FormField`: columna con label pequeño (ícono + texto) + campo + action opcional.
- `_DropdownField`: `DropdownButtonFormField` con deduplicación de IDs, usa `initialValue` (no `value` deprecado).
- `_AddAction`: botón "+" alineado a la derecha para crear frente/fase inline.
- `_NameInputSheet`: modal bottom sheet con `TextField` autofocus para ingresar nombre de nuevo frente/fase.
- `_FieldDivider`: separador interno entre campos.

### Correcciones de lint
- `sort_child_properties_last`: parámetro `action` reordenado antes de `child` en constructor de `_FormField`.
- `value:` deprecated en `DropdownButtonFormField` → cambiado a `initialValue:`.

## 3. `restriction_detail_screen.dart` — Vista de detalle (reescritura)

Pantalla de solo lectura que muestra todos los campos de una restricción. **Diseño homologado al formulario**.

### Estructura visual
- **AppBar:** igual al formulario (fondo `_D.primary`, back arrow explícito, botón editar en actions).
- **Header con gradiente dinámico** según estado/vencimiento:

| Condición | Gradiente |
|---|---|
| `isOverdue` | `0xFFDC2626 → 0xFFEF4444` (rojo) |
| `completed` | `0xFF059669 → 0xFF10B981` (verde) |
| `in_progress` | `0xFFD97706 → 0xFFF59E0B` (amarillo) |
| `pending` (default) | `0xFF0A66B7 → 0xFF1580D8` (azul) |

- Badges en el header (`_HeaderBadge`): fondo blanco translúcido 18%, texto e ícono **blancos** (legibles sobre cualquier color de fondo).
  - Estado con su ícono.
  - Sincronización (`cloud_done` / `cloud_upload`).
  - Si `isOverdue`: `"$daysOverdue días vencido"`.

- **3 secciones** `_DetailSection` (mismo estilo visual que `_FormSection`):
  1. **Ubicación** → Frente, Fase, Área.
  2. **Detalle** → Actividad, Descripción (si existe), Tipo.
  3. **Planificación** → Fecha requerida, Fecha conciliada (si existe), Estado, Responsable, Solicitante, Proyecto, Última actualización.

- **Botón editar** al final: `FilledButton.icon` idéntico al botón guardar del formulario.

### Widgets de soporte
- `_DetailSection`: idéntico a `_FormSection` del formulario.
- `_DetailRow`: ícono pequeño + label gris + valor (sin input, solo texto).
- `_RowDivider`: separador entre filas de detalle.
- `_HeaderBadge`: badge siempre blanco (sin parámetro `color` — el fondo del header ya provee el color semántico).

## Convenciones clave (aplicables a toda la app)

- **Sin `AppTheme`** en pantallas rediseñadas → paleta local `abstract final class _D`.
- **Sin `boxShadow`** → bordes con `Border.all(color: _D.stroke)`.
- **`.withValues(alpha: x)`** en lugar de `.withOpacity(x)` (deprecado en Flutter reciente).
- `AppScope.of(context)` devuelve `AppController` — es el único punto de acceso al estado.
- `ctrl.catalogs.statuses` → `List<CatalogOption>` (campos: `id: String`, `label: String`).
- Métodos del controller usados: `findRestrictionById`, `updateRestrictionStatus`, `deleteRestriction`, `saveRestriction`, `createRestrictionFront`, `createRestrictionPhase`.
- `RestrictionFormArgs(restrictionId: int?)` — si `null`, es creación; si tiene valor, es edición.
- `RestrictionDetailArgs(restrictionId: int)` — siempre requerido.
