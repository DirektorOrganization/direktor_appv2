# DIREKTOR MOBILE APP
## INSTRUCCIONES DE INTERACCIÓN ENTRE WIREFRAMES Y ROOT

# 1. OBJETIVO DEL DOCUMENTO

Los wireframes describen la experiencia visual y funcional.

El root del proyecto describe dónde vive cada pieza dentro de la arquitectura Flutter.

Este documento une ambas cosas.

Regla general:

- cada wireframe principal debe mapearse a una pantalla dentro de `features/.../presentation/screens/`
- los bloques internos del wireframe deben mapearse a widgets dentro de `features/.../presentation/widgets/` o `shared/`
- las acciones del wireframe deben resolverse desde un `controller` y sus `usecases`
- la persistencia o consulta de datos debe apoyarse en `repositories`, `datasources`, `db` y `services`
- en móvil, la UI debe trabajar primero con **SQLite local**, mientras que la API remota alimenta ese modelo local

# 4. REGLAS DE INTERACCIÓN ENTRE WIREFRAME Y ARQUITECTURA

## Regla 1
Cada pantalla visible del wireframe debe existir como archivo en:

```text
features/<module>/presentation/screens/
```

## Regla 2
Cada bloque visual reutilizable del wireframe debe convertirse en widget dentro de:

```text
features/<module>/presentation/widgets/
```

o, si es transversal, dentro de:

```text
shared/widgets/
shared/components/
```

## Regla 3
Cada acción del wireframe debe resolverse desde un controller en:

```text
features/<module>/state/
```

## Regla 4
Toda lógica de negocio del wireframe debe pasar por usecases en:

```text
features/<module>/domain/usecases/
```

## Regla 5
Los datos no deben leerse directamente desde la UI; la UI conversa con controller, usecases, repositories y datasources.

## Regla 6
La app móvil debe trabajar primero con **SQLite local**.  
La API remota debe alimentar ese SQLite mediante repositories y sync.

## Regla 7
Toda información de sesión, último proyecto, offline o sync debe usar:

```text
data/datasources/local/
data/datasources/local/db/
data/repositories/
core/services/
```

## Regla 8
La navegación entre wireframes debe centralizarse en:

```text
app/router.dart
app/routes/route_names.dart
app/routes/route_guards.dart
```

```text
LOGIN
  -> autentica contra API
  -> guarda usuario y sesión en SQLite
  -> navega a Proyectos

PROYECTOS
  -> muestra proyecto actual
  -> lee resúmenes locales
  -> permite cambiar proyecto
  -> abre Restricciones, Reuniones o Completadas

RESTRICCIONES - LISTA
  -> lee restricciones del SQLite
  -> resuelve prioridad
  -> filtra
  -> busca
  -> abre Detalle o Formulario

RESTRICCIONES COMPLETADAS
  -> lee completadas locales
  -> busca
  -> pagina online si hay conexión
  -> limita offline

RESTRICCIÓN - DETALLE
  -> muestra data local completa
  -> permite editar

RESTRICCIÓN - FORM
  -> crea o edita localmente
  -> valida
  -> guarda
  -> agrega a sync_queue
  -> recalcula resumen

ACTAS / REUNIONES
  -> lee reuniones y acuerdos desde SQLite
  -> muestra seguimiento
  -> recalcula resumen cuando cambie información
```
