## Resumen funcional consolidado

### 1. Fase 1
- La leyenda de estados de Fase 1 paso a comportarse igual que Fase 2 y Fase 3.
- Ahora existe un estado activo seleccionable desde la leyenda inferior.
- `1 click` sobre una posicion aplica el estado activo actual.
- `2 clicks` sobre una posicion ciclan al siguiente estado, lo dejan activo y lo aplican a la posicion.
- Se agrego soporte explicito en controlador y repositorio para actualizar el estado de una posicion de Fase 1, en lugar de depender solo del ciclo automatico.
- Se hicieron ajustes para reducir re-fits innecesarios del editor de Fase 1 ante refresh de datos que no cambian la geometria real del plano.

### 2. Fase 2
- Se corrigio el centrado y zoom al seleccionar una actividad desde el listado inferior de actividades.
- El calculo ahora toma mejor la posicion real dentro del contenido del `InteractiveViewer`, reduciendo el error donde solo la primera actividad centraba correctamente.
- Se alineo la interaccion de la leyenda de estados para que el estado activo tambien pueda seleccionarse tocando directamente el indicador inferior.

### 3. Fase 3 - Matriz y gestion por piso
- La matriz `actividad x sector x piso` fue ajustada para compartir correctamente el scroll horizontal entre encabezados y celdas, manteniendo fija la columna de actividades.
- Tambien se sincronizo el desplazamiento vertical entre la lista de actividades y la tabla de celdas cuando hay muchas filas.
- La franja superior del piso ya no usa la lista inline de sectores.
- En su lugar se agregaron acciones explicitas para administrar recursos del piso:
  - `Administrar pisos`
  - `Administrar sectores`
  - `Administrar actividades`
  - `Ver plano` / `Ver matriz`
- El boton `Agregar actividad` dentro del header de la matriz se mantuvo operativo y sin cambios de comportamiento.

### 4. Fase 3 - Modales de administracion
- `Administrar sectores` y `Administrar actividades` ya no se presentan como dialogos centrados.
- Ahora se muestran como bottom sheets saliendo desde abajo, tomando como referencia visual el listado de actividades de Fase 2.
- Ambos incluyen buscador local por nombre/abreviacion.
- Ambos incluyen accion visible de alta:
  - `Agregar nuevo sector +`
  - `Agregar nueva actividad +`
- Los registros globales se muestran solo como lectura.
- Los registros locales del piso muestran acciones visibles de `Editar` y `Eliminar`.
- `Eliminar` conserva confirmacion inline desde el mismo boton del registro.
- `Editar` y `Agregar` abren un segundo bottom sheet encima del listado, sin cerrar el panel de administracion que queda debajo.

### 5. Fase 3 - Formulario superior de crear/editar
- El formulario de crear/editar sector o actividad reutiliza `_P3AddItemModal`, pero ahora puede abrirse con barrera transparente para no oscurecer el listado inferior.
- Se ajusto su estilo para acercarlo al formulario de la propuesta 1:
  - fondo gris en vez de blanco pleno
  - ancho completo dentro del espacio disponible
  - boton pequeno de guardado alineado a la derecha
  - texto de cancelacion explicito en lugar de `X`
  - `Cancelar edicion` para edicion
  - `Cancelar insercion` para nuevos registros
- El texto del boton principal se especializo por contexto:
  - `Agregar sector`
  - `Agregar actividad`
  - `Guardar` en edicion segun el flujo de cada recurso

### 6. Fase 3 - Vista de planos
- Se incorporo soporte operativo para subir y descargar planos por piso.
- El plano descargado se guarda localmente y se reutiliza mientras siga disponible en almacenamiento del dispositivo.
- Se corrigio el flujo de posicionamiento de sectores para que el cambio se guarde como update de `avagra_sectoresxpisos` y no por una ruta remota separada fuera de la cola/eventos esperados.
- Se alineo la lectura de `jsonPosicionamientoPlano` con el formato usado por web (`x`, `y` normalizados).
- Se agregaron controles de zoom flotantes y mejoras de render para evitar deformar el plano usando dimensiones reales de la imagen.
- Se hicieron varios ajustes iterativos sobre el marcador visual de sectores en plano:
  - compensacion de tamano cuando el plano esta muy alejado
  - aumento del tamano base del circulo
  - mejora del feedback al arrastrar

### 7. Soporte de sync y cliente remoto
- Se hicieron ajustes en clientes remotos y flujo de sync para soportar mejor operaciones relacionadas con Avance Grafico y evitar caminos paralelos no alineados con la cola de eventos.
- Se corrigieron detalles de `analyze` y de composicion de payloads/headers en archivos de soporte remoto actualmente modificados.
