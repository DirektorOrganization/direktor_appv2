# Plan Estrategico y Arquitectura Web: DIREKTOR (Version 2)

## 1. Objetivo de esta version
Este documento complementa la estrategia inicial con enfoque comercial, arquitectura de conversion y guia de creacion de imagenes/banners autogenerados para la nueva web de Direktor.

La web debe comunicar con claridad que Direktor es una plataforma de gestion operativa para construccion que integra:
- web + mobile
- trabajo en campo offline-first
- trazabilidad de restricciones, acuerdos, actas e hitos
- tableros, indicadores y reportes automaticos
- alertas y automatizaciones (incluido canal WhatsApp cuando aplique)

---

## 2. Posicionamiento y mensaje central
### 2.1 Propuesta de valor principal
"Direktor transforma restricciones, reuniones, acuerdos e hitos en gestion visible, ordenada y accionable."

### 2.2 Mensajes clave por audiencia
- Gerencia / Direccion de proyecto: visibilidad ejecutiva, indicadores y control de riesgo.
- Oficina tecnica / Planeamiento: seguimiento estructurado de restricciones e hitos.
- Campo (residentes, supervisores, contratistas): registro rapido, trazabilidad, operacion mobile offline.

### 2.3 Diferenciales competitivos a resaltar
- Operacion real en obra (no solo escritorio): mobile + offline + geolocalizacion.
- Seguimiento con trazabilidad: acuerdos, responsables, fechas y evidencias.
- Alertas y automatizacion: menos control manual, mas accion oportuna.
- Lectura ejecutiva: tableros e indicadores para decidir rapido.
- Adopcion facil e integracion segura: Acompanamiento dedicado (Customer Success), proteccion cloud empresarial y conexion fluida a software existente.

---

## 3. Oferta de Direktor en la web
### 3.1 Modulos principales (nucleo funcional)
Presentar como "5 modulos principales" + "capacidades transversales".

1. Analisis de Restricciones
- Registro, priorizacion, estado y vencimientos.
- Semaforizacion y seguimiento por responsable.

2. Actas de Reuniones
- Registro estructurado de reuniones.
- Trazabilidad de asistentes, acuerdos y compromisos.

3. Seguimiento de Acuerdos
- Vista operativa de acuerdos pendientes, por vencer y vencidos.
- Control de responsables y fechas compromiso.

4. Control de Hitos
- Seguimiento de eventos criticos y fechas clave.
- Deteccion de hitos en riesgo y cumplimiento.

5. Avance Grafico
- Lectura visual del progreso de obra.
- Comunicacion ejecutiva de estado y avances.

### 3.2 Capacidades transversales (servicios de alto valor)
- Tableros, indicadores y reportes automaticos.
- Alertas y notificaciones inteligentes (incluyendo WhatsApp cuando aplique).
- Operacion mobile y sincronizacion offline-first.
- Geolocalizacion para contexto de campo.
- Automatizaciones operativas y de reporteria.
- Integracion de software (ej. MS Project, Primavera P6, ERPs) para eliminar doble digitacion.

---

## 4. Arquitectura web recomendada (sitemap)
Se recomienda web corporativa multi-pagina + secciones de conversion.

1. Inicio
- Hero de alto impacto con CTA dual: "Solicitar demo" y "Ver modulos".
- Bloque de problema real en obra vs solucion Direktor.
- Resumen de modulos y capacidades transversales.
- Prueba social (clientes/sectores/testimonios).
- CTA final con formulario corto.

2. Plataforma
- Vista general de como se conectan web + mobile + offline.
- Flujo operativo: Captura en campo -> sincronizacion -> tablero -> accion.
- Beneficios por rol (gerencia, oficina tecnica, campo).

3. Modulos
- Landing de modulos con 5 tarjetas (uno por modulo principal).
- Pagina detalle por modulo (beneficios, casos de uso, KPI objetivo, FAQ).

4. Servicios, Automatizacion e Integraciones
- Alertas inteligentes y automatizaciones.
- Reporteria automatica y tableros.
- Integraciones operativas agiles (conexion con ERP/cronogramas) para fluidez de datos.
- Integraciones de comunicacion (ej. WhatsApp) cuando aplique al cliente.

5. Tecnologia, Customer Success y Seguridad
- Customer Success (Acompanamiento): Proceso de onboarding guiado en obra y soporte que garantiza la masiva adopcion sin friccion del equipo en campo.
- Privacidad y Compliance: Arquitectura cloud con maximas politicas de seguridad y confidencialidad corporativa ("sus actas, sus datos").
- Offline-first y trazabilidad total.
- Geolocalizacion y soporte nativo para operacion movil fluida.

6. Casos de uso / Casos de exito
- Escenarios reales: restricciones criticas, reuniones con acuerdos, control ejecutivo.
- Formato problema -> implementacion -> resultado.

7. Contacto, Modelos de Planes y Demo
- Bloque de FAQ (Preguntas Frecuentes): Aclaracion de escalabilidad y precios por rol/proyecto para pre-cualificar al usuario que llega y resolver quejas tipicas.
- Formulario B2B orientado a ventas consultivas para agendar recorridos y demos guiadas.
- Boton de WhatsApp directo para respuestas agiles o urgentes.
- Campos minimos del formulario: nombre, empresa, rol, tamano de obra, dolor o necesidad principal.

## 5. Arquitectura de conversion (muy importante)
### 5.1 CTAs principales
- Primario: Solicitar demo
- Secundario: Hablar por WhatsApp
- Terciario: Descargar brochure / Ver caso de uso

### 5.2 Embudo sugerido
1. Descubrimiento: Home + contenido de valor
2. Consideracion: Paginas de modulos y servicios
3. Decision: Caso de exito + prueba social + formulario
4. Cierre: Agenda de demo y seguimiento comercial

### 5.3 Microconversiones para no perder trafico frio
- Descarga de brochure tecnico-comercial
- Ver video demo de 60-90 segundos
- Suscripcion a novedades/product updates

## 7. Lineamientos UX/UI para la web
- Mensajes concretos, orientados a resultados operativos.
- Lenguaje simple (evitar tecnicismos innecesarios en home).
- Jerarquia visual: problema -> solucion -> prueba -> accion.

## 8. Guia para creacion de banners e imagenes autogeneradas
Objetivo: asegurar consistencia visual y mensajes comerciales claros en piezas generadas por IA.

### 8.1 Tipos de piezas a producir
1. Hero principal (portada home)
2. Banner por modulo (5 modulos)
3. Banner de servicios (offline, alertas, reporteria, geolocalizacion)
4. Imagen para casos de uso
5. Creativos para campañas (Meta/LinkedIn/WhatsApp)

### 8.2 Formatos y tamanos recomendados
- Web hero desktop: 1920 x 1080
- Web hero mobile: 1080 x 1350
- Banner interno: 1600 x 900
- Post cuadrado: 1080 x 1080
- Story / vertical: 1080 x 1920

### 8.3 Estilo visual sugerido
- Contexto: obra moderna + interfaz digital visible.
- Tono: profesional, tecnologico, operativo (no futurismo exagerado).
- Evitar: fotos de stock genericas sin relacion con construccion.
- Incluir elementos visuales de: tableros, alertas, mapas/geolocalizacion, lineas de progreso.

### 8.4 Plantilla de prompt maestro (para IA de imagen)
Usar esta base y reemplazar campos entre corchetes:

"Crear [tipo de pieza] para Direktor, plataforma de gestion de proyectos de construccion. Mostrar [escena principal] con enfoque en [modulo/servicio]. Estilo corporativo moderno, colores azul oscuro + azul medio + acento naranja, composicion limpia, alto contraste, lectura clara para texto superpuesto, formato [tamano]. Incluir elementos visuales de [indicadores/alertas/geolocalizacion/offline], evitar apariencia de stock generico, resultado profesional B2B."

### 8.5 Prompts listos por modulo/servicio
1. Restricciones
"Banner web 1600x900, ingeniero revisando tablero de restricciones con semaforizacion, tarjetas de pendientes y vencimientos, entorno de obra real, estilo corporativo Direktor, limpio y moderno."

2. Actas y acuerdos
"Banner web 1600x900, reunion de obra con interfaz digital mostrando acta, acuerdos, responsables y fechas, enfoque en trazabilidad y seguimiento."

3. Control de hitos
"Banner web 1600x900, linea de tiempo de hitos con estados cumplido/en riesgo, visual ejecutivo, obra en segundo plano, estilo profesional B2B."

4. Avance grafico e indicadores
"Banner web 1600x900, dashboard de avance de proyecto con graficos de progreso, alertas y KPI, lectura clara para gerencia de obra."

5. Mobile offline + geolocalizacion
"Banner web 1600x900, supervisor en campo usando app mobile sin conexion, mapa con geolocalizacion, sincronizacion posterior al recuperar red."

6. Alertas y automatizaciones (incluye WhatsApp)
"Banner web 1600x900, flujo de alertas automaticas hacia panel y WhatsApp, notificaciones de vencimientos y acuerdos criticos, estilo sobrio y corporativo."

### 8.6 Checklist de calidad antes de publicar
- El mensaje visual corresponde al modulo/servicio correcto.
- Hay espacio limpio para titular y CTA.
- No hay texto ilegible ni artefactos IA notorios.
- La imagen se ve bien en desktop y mobile.
- El tono visual coincide con marca Direktor.

## 9. Roadmap de ejecucion recomendado

- Cerrar narrativa comercial y arquitectura final.
- Aprobar copy base de Home, Plataforma, Modulos y Servicios.

- Lanzamiento + optimizacion por conversion.
